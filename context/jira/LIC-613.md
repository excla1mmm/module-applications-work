## Описание (Jira wiki)

h2. Цель и контекст
Доверенно и идемпотентно регистрировать новый модуль из одобренной заявки за проверенным издателем-пользователем. Развитие MVP по плану пользователя от 21.10.2026. Существующие задачи и их исторические критерии не переписываются. Новая цепочка: заявка → проверки → ручное одобрение конкретного SHA → merge → регистрация модуля; публикация версии — отдельная операция. Без отдельной платформы модерации.
Уже сделаны LIC-310 (Publishers, github_id, ReleasesTypes.publisher_id), LIC-311/343 (токен и владение), LIC-317 (internal API), LIC-314/345 (публикация/отзыв). Они переиспользуются; новый API с нуля не проектируется.

h2. Границы
Дополнить существующий API только недостающим контрактом регистрации по заявке и подтверждения владения. Издатель — строка Publishers в тенанте MIKO, не новый tenant и не произвольный publisher_id из YAML.

h2. Критерии приёмки
* [ ] Определён способ подтверждения связи GitHub-пользователя со стабильным github_id существующего активного Publishers либо подтверждение из авторизованного кабинета. github_login, авторство PR и publisher_id в YAML сами по себе не дают права регистрировать модуль от чужого имени.
* [ ] Регистрация принимает доверенное свидетельство одобренной заявки: module_id/GUID, подтверждённый publisher_id, репозиторий, полный SHA, ревизию манифеста, результат проверки и ручное решение. Проверяется актуальность всей связки; поддельные/устаревшие результаты отвергаются.
* [ ] Существующие module_id другого издателя или тенанта не перехватываются; официальный модуль не превращается в сторонний. Для уже зарегистрированного совпадающего запроса повтор возвращает тот же результат; конфликтующий SHA/владелец не перезаписываются молча.
* [ ] Идемпотентность выдерживает повтор после потерянного ответа и конкурентные вызовы; в аудите доступны заявка, владелец, SHA и решение, без секретов.
* [ ] Регистрация создаёт/закрепляет карточку и допуск модуля, но не загружает и не публикует версию. Прежний переход released 0→1 с публикацией ожидающих stable (LIC-314/317) не становится обходом будущего гейта проверки каждого релиза.
* [ ] Право издателя ограничено своими допущенными модулями; новый GUID требует новой заявки, блокированный издатель не получает право загрузки/регистрации. Проверка владения выполняется на сервере, а не только в UI.
* [ ] Контракт и ошибки документированы; тесты покрывают чужого издателя, подмену YAML, конфликт GUID, блокировку, устаревший SHA, повтор и гонку регистрации. Согласована совместимость с защитой идентичности LIC-553 и полями автора LIC-598.

h2. Зависимости и открытые решения
Блокируется схемой PR-манифеста LIC-611; опирается на LIC-317 и LIC-343. Потребитель — отдельный доверенный workflow после merge. Кабинет GitHub OAuth уже запланирован в LIC-318/338: его не дублировать, согласовать подтверждение личности с этой задачей.
До реализации выбрать существующую точку расширения API, способ передачи доверенного решения и идемпотентный ключ; endpoint и способ аутентификации здесь намеренно не выдумываются. Ограниченные API-права согласовать с LIC-596: не выдавать вендорскому коду полный REST-ключ тенанта.

h2. Проверка и вне скоупа
Интеграционные запросы в тестовом окружении: одна карточка при повторах/конкуренции, чужое владение неизменно, регистрация не меняет видимость версий. Вне скоупа: реализация кабинета целиком, выпуск/ротация ключей в текущем запросе, коммерческие правила, публикация версий.

h2. Дополнение 21.10.2026 — потребитель API и связь с проверенным пакетом
Потребитель регистрационного контракта — отдельный доверенный workflow GitHub Actions (LIC-614). Тесты выполняются в существующих Docker-образах MikoPBX, AI-отчёт формирует агент Claude в отдельной доверенной среде (LIC-612).
* [ ] Доверенное свидетельство связывает source SHA, checksum проверенного ZIP, ревизию заявки, версии правил и ссылки/идентификаторы результатов матрицы MikoPBX (версия, архитектура, digest образа), AI-отчёт и решение человека. Способ хранения метаданных/ссылок определить контрактом, не добавляя произвольный endpoint.
* [ ] Сам текст ответа Claude или присланный издателем отчёт не является разрешением регистрации. Источник решения и его актуальность проверяются независимо от содержания AI-отчёта.
* [ ] Ключ регистрации недоступен контейнеру с модулем и агенту Claude. Идемпотентный повтор после сбоя GitHub Actions сохраняет одну карточку за тем же подтверждённым издателем.
Успешная регистрация по-прежнему не публикует версию: для загруженного в кабинете ZIP проверяется собственная актуальная связь с исходниками и результаты гейта LIC-615.
