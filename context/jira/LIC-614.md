## Описание (Jira wiki)

h2. Цель и контекст
После merge одобренной PR-заявки автоматически зарегистрировать модуль за подтверждённым издателем через контракт LIC-613. Закрыть переход между проверками LIC-612 и сервером лицензирования, не смешивая регистрацию модуля с публикацией версии.
В существующем покрытии есть API издателя и internal API (LIC-317/343), но нет доверенного потребителя результата PR-проверок. LIC-611–613 прочитаны: workflow после merge выделен из их границ и здесь не дублирует разработку API.

h2. Границы
Отдельный доверенный GitHub Actions workflow в module-applications. Он работает с принятой заявкой и доверенными результатами проверок; исходники остаются в репозитории издателя. API и способ аутентификации выбираются в LIC-613, endpoint здесь не задаётся. Изменения доступа и выдача секретов в рамках текущего запроса не выполняются.

h2. Критерии приёмки
* ☐ Запуск регистрации разрешён только для фактически merged заявки из защищённой целевой ветки; закрытый без merge PR, ручной запуск с произвольным YAML и непрошедшая проверки заявка не дают зарегистрировать модуль.
* ☐ До API-вызова доверенно сверяется вся связка: заявка и ревизия манифеста, module_id/GUID, подтверждённый publisher_id, репозиторий, полный SHA исходников, версия правил, успешные обязательные проверки и ручное одобрение именно этой связки. HEAD/тег/текущее состояние ветки не подменяют проверенный SHA. Смена манифеста или исходного SHA после ревью требует новой проверки и одобрения.
* ☐ Workflow не исполняет код/команды/локальные Actions из PR или репозитория издателя рядом с секретами. Не используется pull_request_target для исполнения чужого кода с ключами; fork PR не получает секреты. Артефакт или кэш недоверенного job сам по себе не считается доказательством успешной проверки.
* ☐ Регистрация вызывается от ограниченной доверенной служебной идентичности; publisher_id из YAML не позволяет действовать от чужого имени. Выбранные права согласованы с LIC-613/596; полный ключ тенанта не передаётся вендору или в среду проверки.
* ☐ Повтор workflow, сетевой таймаут после успешной записи и конкурентный запуск используют один идемпотентный ключ по контракту LIC-613 и приводят к одной карточке модуля. Конфликт владельца/заявки/SHA останавливает регистрацию, а не перезаписывает существующий модуль.
* ☐ Результат и ошибка видны сопровождающему; сохранены ссылка на PR и workflow run, одобренный SHA и серверный идентификатор модуля, без токенов. Повтор после сбоя не требует нового модуля или ручного изменения БД.
* ☐ Успешная регистрация не загружает ZIP и не публикует версии. Передаваемый результат пригоден для кабинета LIC-318; новый GUID требует своей заявки.

h2. Зависимости
Блокеры: LIC-611 (манифест), LIC-612 (актуальное решение и проверенный SHA), LIC-613 (идемпотентный API и подтверждённый издатель). Связано: LIC-596 (ограничение ключей), LIC-318 (кабинет). Существующие описания, статусы и сроки не изменять.

h2. Проверка
На тестовом API воспроизвести merged одобренную заявку, PR без merge, замену SHA/манифеста, поддельный отчёт, потерю HTTP-ответа и два параллельных запуска. В положительном случае одна карточка с верным владельцем, в отрицательных — нет регистрации и публикации. Команда запуска определяется реализацией workflow; приложить URL тестового run и результат проверок без секретов.

h2. Файлы/модули и открытые решения
Новый репозиторий module-applications: доверенный workflow и его тестовые сценарии. В текущем checkout каталог .github отсутствует; не предполагать, что workflow уже существует здесь. Точки интеграции в коде сервера лицензий (группа publisher и internal-сохранение типа) известны, но это не готовый контракт регистрации по заявке. До реализации зафиксировать доверенный формат решения, проверку происхождения результата, способ аутентификации и идемпотентный ключ совместно с LIC-613.
Вне скоупа: реализация регистрационного API, выполнение тестов чужого кода, кабинет целиком, загрузка/публикация релизов, отдельная платформа модерации, deployment.

h2. Дополнение 21.10.2026 — три отдельных workflow в GitHub
Для пилота используется публичный module-applications и стандартные GitHub-hosted runners. Предусмотреть отдельные workflows для тестов в Docker MikoPBX, AI-отчёта Claude и регистрации после merge. Это развитие согласованной схемы LIC-612; отдельный постоянно работающий сервер для первоначального пилота не планируется.
* [ ] Защищённая ветка требует успешных обязательных проверок и человеческого одобрения. Изменение заявки/SHA сбрасывает прежнее одобрение. Workflows, проверяющий код и правила допуска защищены от подмены заявкой; учитываются права обхода защиты.
* [ ] Регистрационный workflow получает только проверенный результат цепочки, повторно сверяет его привязку к принятой заявке и вызывает LIC-613. В этой VM не запускается контейнер MikoPBX с чужим модулем и не исполняются файлы PR.
* [ ] Ключ Anthropic доступен только доверенному этапу AI, ключ лицензирования — только регистрации. Передача результатов между workflows проверяет источник запуска, актуальную ревизию/SHA и завершение всех обязательных этапов; пустой отчёт или исчерпанный бюджет не разрешают регистрацию.
* [ ] Ошибку/повтор API-вызова видно в GitHub; сохранены ссылки на run, тестовые результаты, AI-отчёт и серверный результат. Тяжёлые артефакты имеют ограниченный срок хранения, при этом данные аудита допуска сохраняются.
Нынешнее действие — дополнение Jira. Создание репозиториев, настройка secrets, защиты веток и запуск workflows выполняются на этапе реализации, не считаются уже сделанными.
