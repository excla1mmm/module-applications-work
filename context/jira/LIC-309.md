## Описание (Jira wiki, сокращено: статус выката и комментарии убраны для публичного репозитория)

Сторонние авторы смогут публиковать свои модули (бесплатные и платные) в маркетплейсе MikoPBX без ручной проверки каждого релиза. Этот эпик — серверная часть: издатели, API загрузки релизов, проверка архивов, отзыв версий, новые поля каталога.

h3. Согласованные правила первого этапа (10.10.2026)
* Допуск выдаёт MIKO издателю для конкретного GUID модуля. Новый GUID проходит отдельный допуск; право на один модуль не открывает остальные.
* Перед допуском агент проверяет любой один ZIP этого GUID, уже загруженный на сервер для публикации. Отчёт содержит GUID, версию и sha256, вычисленный сервером. Проверяется загруженный артефакт, а не текущее состояние репозитория.
* Блокируют допуск нарушения безопасности и обязательного контракта/стандартов совместимости MikoPBX. Каждый блокер ссылается на конкретное требование. Рекомендации, в том числе по стилю, перечисляются отдельно и не препятствуют допуску.
* До допуска stable и draft скрыты от обычного каталога (служебный предпросмотр — по LIC-315). При переходе {{ReleasesTypes.released}} 0→1 все ожидающие неотозванные версии с исходным {{channel=stable}} публикуются сразу, без повторного {{/publish}}. {{draft}} остаются скрытыми. Допуск не снимает отзыв версии.
* Последующие stable-версии принятого GUID публикуются без обязательного нового агентского ревью; draft публикует сам издатель через {{/publish}}. Структурная проверка каждого ZIP в HTTP-загрузке остаётся обязательной и не исполняет код архива.
* Публикация исходников необязательна, {{source_url}} опционален для всех издателей. Публичный {{support_email}} обязателен и должен иметь корректный формат; {{contact_email}} — отдельный приватный контакт.
* {{community}} — бесплатные модули; платные сторонние модули — {{verified}} по договору. MIKO проверяет это при допуске и последующих изменениях платности, товаров/фич или уровня издателя. Издательский API этими полями не управляет. Дополнительная перекрёстная серверная валидация в шаг 1 не входит.
* {{status=blocked}} немедленно закрывает API и кабинет издателя, но сохраняет доступность ранее опубликованных версий. Отзыв конкретной версии оформляется отдельно.
* {{withdrawn=publisher}} скрывает релиз без предупреждения установленным АТС; издатель может вернуть его через {{/publish}} после допуска GUID. {{withdrawn=moderation}} скрывает релиз и попадает в карту {{revoked}} с причиной; издатель снять такой отзыв не может. Автоотключения установленного модуля нет.
* Ранее выданные многоразовые ссылки ZIP остаются рабочими после снятия или отзыва; каталог перестаёт выдавать ссылку на скрытую версию. Автоматическое удаление файла/закрытие share в этот этап не входит.
* Агентское ревью — внутренний процесс. Пользователь видит издателя, категорию доверия и предупреждение о стороннем коде; никакого обещания проверки или гарантии безопасности/качества кода. Публичный email ведёт в поддержку издателя; ссылка на исходники показывается только при наличии.
* Центральная адресная рассылка владельцам затронутой версии — отдельная идея LIC-446 для сторонних и официальных модулей, не условие запуска первого этапа.

Эти правила и обновлённые критерии дочерних задач заменяют ранние формулировки обсуждения. Ссылки на спецификацию и планы ниже сохранены как технический контекст; их синхронизация включена в LIC-319 и LIC-320 до реализации соответствующих частей.

*Спецификация:* mikopbx/Core, ветка docs/third-party-modules-spec, [docs/superpowers/specs/2026-09-21-third-party-modules-design.md|https://github.com/mikopbx/Core/blob/docs/third-party-modules-spec/docs/superpowers/specs/2026-09-21-third-party-modules-design.md] (разделы в задачах — по ней).

*Шаг 1 обеспечивает:*
# у каждого стороннего модуля есть издатель, публиковать релизы может только он (Bearer-токен, скоуп по GUID);
# файл на АТС = файл, принятый сервером (sha256, https);
# администратор АТС видит издателя и уровень доверия (official / verified / community) до установки;
# MIKO может отозвать версию, администраторы установленных АТС получают предупреждение.

*Разбиение на эпики (02.10.2026):* этот эпик — только сервер лицензий (сервер лицензий, модуль Releases), один выкат; ядро MikoPBX — LIC-337; кабинет издателя (шаг 1б) — LIC-338.

*Состав:*
* сервер лицензий (сервер лицензий, модуль Releases) — задачи этого эпика в LIC;
* ядро MikoPBX — эпик LIC-337, issues в GitHub mikopbx/Core #1134–#1140 ([метка marketplace|https://github.com/mikopbx/Core/issues?q=label%3Amarketplace]), список и зависимости — в задаче «Ядро MikoPBX» этого эпика;
* контракт сервер↔АТС — раздел 5 спецификации, поля только добавляются.

*Не цели шага 1:* EdDSA-подпись ZIP, подписанный ответ каталога, автоотключение модулей, канал beta, второй способ входа в кабинет, выплаты авторам.

*Порядок работ:* сервер (модель данных → токен и маршруты → приём ZIP → гейт → правило чтения → поля контракта → VendorCabinet) и ядро параллельно; затем пример CI и онбординг, сквозной прогон, пилот на ModuleCalleridSearchCH; кабинет издателя — последним (шаг 1б).
