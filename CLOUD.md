# Инструкция для облачной сессии-исполнителя

Ты работаешь в облачном контейнере (x86_64). Задача — этапы 0–2 из `EXECUTOR_PROMPT.md`.
Этот файл уточняет промпт под облако; при расхождении действует этот файл.

## Что где

| Файл | Что это |
|---|---|
| `TASK.md` | Главное ТЗ: архитектура, черновик манифеста, критерии приёмки, открытые вопросы |
| `EXECUTOR_PROMPT.md` | Задание на этапы 0–2 (написан для Mac — см. поправки ниже) |

| `requests/README.md` | Как попросить сессию на Mac: Jira, arm64, локальный Core |

## Поправки к EXECUTOR_PROMPT.md для облака

1. **Пути.** Пути `/Users/excla1m/...` — это Mac. У тебя репозиторий — этот клон. Core, ModuleTemplate, oss-scanner
   клонируй с GitHub сам (`mikopbx/Core` ветка `develop`, `mikopbx/ModuleTemplate`, `anthropics/oss-scanner`).
2. **Jira.** Доступа нет. Не пытайся. Чтение — из `context/jira/`. Запись (start LIC-611 с планом, комментарии с
   находками, итог done) — оформляй запросом `jira-write` в `requests/` с готовым текстом. Первый запрос сразу:
   `start LIC-611` с планом 3–5 строк.
3. **Ветки.** Работа — в своей ветке (`claude/...`), пуш разрешён. В `main` пушь **только** файлы `requests/NNN-*.md`.
   `TASK.md` правь в своей ветке (раздел §7 — найденные ответы), сольём при ревью.
4. **arm64.** Здесь только x86_64. Всё делай и проверяй на x86_64; прогон на arm64 (локальный `tools/check` и
   ручной цикл установки) — запросом `mac-run` с веткой и командой, когда будет что гонять.
5. **GitHub Actions / песочница.** Для этапа 2 нужен публичный тестовый репозиторий (arm64 runners бесплатны только в
   публичных). Не создавай сам: когда workflows будут готовы локально, сделай запрос `other` — какой репозиторий,
   что в него положить, какие настройки. Пользователь решит, Mac-сессия создаст.
6. **Docker-образ.** Используй `mikopbx/mikopbx` с Docker Hub; запиши тег и digest для amd64 (и arm64 из манифеста).
   Если в контейнере не хватает прав (`--privileged`, systemd, сеть) — зафиксируй, что именно, и попробуй обойти;
   не можешь — запрос `mac-run`.
7. **Репозиторий публичный.** Никаких внутренних данных MIKO (прод, инфраструктура, закрытый сервер лицензий, ФИО/логины) нигде в репозитории, включая requests/. Если для работы нужна такая информация, проси у пользователя в чате. **Без секретов.** Ключ Anthropic на этапах 0–2 не нужен. Никаких токенов в коммитах и запросах.

## Порядок

1. Прочитай `TASK.md`, `EXECUTOR_PROMPT.md`, `context/jira/LIC-611.md`, `LIC-612.md`.
2. Запрос `001-jira-start-lic-611` (jira-write) с планом.
3. Этап 0 на x86_64 → коммит заметок (команды, digest, вызовы API установки/удаления) в своей ветке.
4. Этап 1 → этап 2 по `EXECUTOR_PROMPT.md`.
5. На вехах — запрос `jira-write` с комментарием о прогрессе (что сделано, чем проверено, коммит).
6. В конце — отчёт пользователю + запросы: arm64-прогон, создание песочницы, итог в Jira.

Пиши пользователю коротко: что сделал, что проверил, какой запрос ждёт Mac.
