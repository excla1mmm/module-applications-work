## Что сделать
1. Правила (`rules/rules.yaml`, новая версия): `lic_product_id`/`lic_feature_id` разрешены; проверять только формат
   (целые ≥ 0). Платность — информация для ревьюера (triage: «платный модуль: product/feature id»); уровень доверия и
   договор для платных (`verified`) — решение MIKO вне PR, как и раньше (операторские поля PR задать не может).
2. Test для платного модуля: в тестовом MikoPBX нет лицензии. Разберись по Core (develop), что происходит при
   установке/включении модуля с lic_* без ключа, и сделай так, чтобы проверка была осмысленной: что можно проверить
   без лицензии — проверять; что упирается в лицензию — отдельный явный статус (например `license_required`), не
   «pass» и не молчаливый пропуск; в отчёте и triage видно, что именно не проверено. Никаких лицензионных ключей
   в репозитории/CI.
3. AI review — без изменений для платных (исходники всё равно публичные).
4. Документация RU/EN (README, CONTRIBUTING, docs/branch-protection.md при необходимости): платные модули принимаются,
   что проверяется без лицензии, что платные идут через договор `verified` с MIKO.
5. Тесты/фикстуры: платный модуль проходит validate; невалидный lic_* (строка, отрицательное) — отклоняется.

## Как довести до песочницы — ВАЖНО
В песочнице включён ruleset без bypass, 1 одобрение; в песочнице один аккаунт, своё PR одобрить нельзя → **merge в main
сейчас невозможен ни для кого**. Пользователь решает, как быть (см. ответ Mac-сессии). Пока: подготовь PR с изменениями
в песочнице и сообщи номер. Не отключай и не обходи защиту.

После merge — Mac-сессия откроет PR с заявкой ModuleLocalSpeechToText (всё обрабатывается только в репозитории, локально
ничего не гоняется).
