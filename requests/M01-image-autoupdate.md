# M01 (от Mac / пользователя → облаку): автообновление закреплённого образа MikoPBX

Тип: задание исполнителю. Решение пользователя 27.10.2026.

## Что сделать
Образ остаётся закреплённым по digest в `config/mikopbx.yaml` (не `latest`) — это правильно: воспроизводимость,
привязка одобрения к окружению, защита от подмены тега. Добавить механизм обновления в духе Dependabot:

1. `.github/workflows/image-update.yaml` — по расписанию (раз в сутки) + `workflow_dispatch`:
   - узнать, куда указывает `mikopbx/mikopbx:latest` (multi-arch index digest + версия MikoPBX, platform digest
     amd64/arm64) — без pull полного образа, через registry API / `docker buildx imagetools inspect`;
   - если digest отличается от `config/mikopbx.yaml` — открыть (или обновить существующий) PR, меняющий только
     `config/mikopbx.yaml`: тег, index digest, platform digests, версия; в описании — старая/новая версия и ссылка на релиз;
   - права: `contents: write`, `pull-requests: write` только у этого workflow; никаких сторонних секретов
     (встроенный GITHUB_TOKEN). Чужого кода не исполняет.
2. На таком PR должны прогоняться контрольные модули (ModuleAppCheck, ModuleAppBroken, ModuleAppProbe) на x86_64 и arm64
   — новый образ становится эталоном только после зелёного прогона и merge человеком. Учесть: PR, созданный
   GITHUB_TOKEN, не триггерит другие workflows — выбрать рабочий способ (вызов test-job из того же workflow /
   `workflow_call` / явный dispatch) и описать в комментарии к workflow.
3. Смена образа = смена тестового окружения: результаты и одобрения открытых заявок, полученные на старом digest,
   становятся неактуальными (как при смене SHA). Отразить в документации (README/CONTRIBUTING RU/EN) и в логике
   проверки актуальности, если она уже есть.
4. Опционально, если просто: матрица заявки — закреплённый эталон + минимальная поддерживаемая версия из
   `compatibility.min_pbx_version`, если для неё есть образ. Если нет — запиши как открытый вопрос в TASK.md §7.

## Проверка
Локально — тест на логику сравнения (фикстура «digest совпал → ничего», «изменился → PR с правильным diff»).
В песочнице (после 004) — ручной `workflow_dispatch` с подменённым digest в конфиге открывает PR.

## Результат
Коммит в твоей ветке; при вехе — запрос jira-write с коротким комментарием в LIC-612 (окружение тестов).
